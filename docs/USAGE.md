# 使用说明

## 来源与更新

| 包裹来源 | 查询方式 |
|---|---|
| 手工添加 | 配置快递100后按承运公司与真实运单查询 |
| 淘宝 | 使用包裹关联淘宝账号，订单页或菜鸟查询 |
| 京东 | 使用包裹关联京东账号查询 |
| 拼多多 | 公司明确、运单有效且快递100已启用时独立查询，否则通过拼多多账号查询 |

手工包裹在平台同步后仍保留。真实平台后来获取到同一运单时，会合并为对应平台来源。

打开详情会按缓存策略查询；点击刷新可主动更新，但不能绕过快递100至少31分钟的每单限频。首页同步会查询未签收的手工运单。自动查询需要开启包裹追踪并设置轮询间隔。

平台登录态失效、手机App与网页登录互踢、安全验证都由平台控制。完成验证后在本站确认登录，不要连续重复请求。快递100只更新已知运单，不能获取新的购物订单。

## 快递100

在开放平台开通实时查询服务后，将 Customer 和 Key 填入本项目设置并启用。请选择真实承运公司；“拼多多快递”只是占位名称，需要在编辑页改为真实公司。订单号和PO-占位号不能当作运单号。

顺丰、中通等需要查件手机号；电商虚拟号码按快递100要求填写横线后的四位。普通接口不保证提供取件码或柜号，可参考官方通知并手动补填。本项目不额外调用收费的取件码或ETA增值接口。

## 待取件与Telegram

在设置中填写 Bot Token、接收 Chat ID 并开启 Telegram 推送。请先在 Telegram 中与自己的 Bot 建立会话，并确认 Bot 可以向目标聊天发送消息。

检测到待取件时会发送公司、运单号、柜号/位置、取件码及最新动态。此提醒不要求开启追踪。非丰巢也会发送取件码；丰巢柜号支持从轨迹解析或手动填写。

- 相同柜号和取件码只发送一次，重启后仍去重。
- 柜号或取件码补全后再次提醒。
- 信息缺失会明确标注，不猜测号码。
- 发送失败5分钟后重试，关闭/未配置推送不会消耗提醒记录。
- 同步结束及后台每分钟检查本地数据；具体上游数据的新鲜度取决于平台同步和物流查询。
- 开启追踪的包裹另有普通动态提醒；待取件包裹会跳过普通提醒以免重复。

## 列表、取件与日报

在途页按最新物流时间降序，缺失时间放后面。主页显示所有来源已获取的取件码。丰巢待取件区域显示柜号/位置与码，缺失可在编辑页补填。

投柜签收但明确要求领取的包裹显示待取件；最新轨迹确认已领取后显示完成，不会因历史投柜轨迹再次变成待取件。

日报采用本地模板，支持定时生成和Telegram推送，不需要模型服务或AI Key。
